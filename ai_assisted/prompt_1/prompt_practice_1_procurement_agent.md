# Practice Interview Prompt 1: Procurement Decision Agent

## Context

You're building a backend system for Dryft that automates purchase order decisions for a manufacturing company. The system connects to the customer's ERP and must decide **what to reorder, how much, and from which supplier** — daily, autonomously.

## Part A — Data Modeling (10 min)

Design SQLModel schemas for the following domain:

- **Parts**: each has a SKU, description, unit cost, lead time (days), minimum order quantity, and a text description (which will be embedded for similarity search).
- **Suppliers**: each supplies multiple parts at different prices and lead times.
- **Inventory Snapshots**: daily snapshots of current stock levels per part per warehouse.
- **Purchase Orders**: generated by the agent — line items, quantities, chosen supplier, status (draft/submitted/confirmed), reasoning (why the agent chose this).

Requirements:
- Use SQLModel with Pydantic v2 validation.
- The `description` field on Parts should support pgvector similarity search (384-dim embeddings).
- Add appropriate validators (e.g., unit cost > 0, lead time > 0, MOQ >= 1).

## Part B — FastAPI Endpoints (10 min)

Build the following endpoints:

1. `POST /parts/search` — takes a natural language query, embeds it, and returns the top-k most similar parts using pgvector cosine distance.
2. `GET /inventory/{warehouse_id}/low-stock` — returns all parts where current stock is below `safety_days * avg_daily_usage` (both configurable via query params).
3. `POST /purchase-orders/generate` — triggers the procurement agent for a given warehouse. Returns a draft PO with the agent's reasoning.

Think about:
- Dependency injection for DB sessions
- Proper error handling and status codes
- Response models (don't leak internal fields)

## Part C — Agent Design (15 min)

Using Pydantic AI's agent framework, design a procurement agent that:

1. Receives a list of low-stock parts
2. For each part, retrieves supplier options (price, lead time, MOQ)
3. Decides optimal order quantities considering:
   - Current stock vs. safety stock
   - Supplier lead times vs. urgency
   - Bulk discount thresholds
   - Budget constraints (passed as context)
4. Returns a structured `PurchaseOrderDraft` with per-line reasoning

Sketch out:
- The agent's system prompt
- Tool definitions the agent can call (e.g., `get_supplier_options`, `get_demand_forecast`, `check_budget_remaining`)
- The structured output schema (Pydantic model)
- How you'd trace/observe this in Langfuse

## Part D — Discussion (10 min)

- How would you test this agent? What's your strategy for evals?
- The agent sometimes picks the cheapest supplier even when lead time would cause a stockout. How do you fix this — prompt engineering, tool design, or post-processing constraints?
- How would you schedule this to run daily via Dagster?
- A customer says "the agent ordered 10,000 bolts but we only use 50/day." How do you debug this?
